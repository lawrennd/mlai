# CIP-0007: Implement Unified Optimization Interface and Algorithms

## Status
- [x] Proposed
- [x] Accepted
- [x] In Progress
- [ ] Implemented
- [ ] Closed

## Summary
Implement a unified optimization interface for trainable models and a shared optimiser module so course-relevant first-order methods (SGD, Adam, …) can drive more than one model family. This is the HOW for [REQ-0007](../requirements/req0007_shared-optimization-surface.md).

## Motivation
Different model types historically used inconsistent training hooks: linear models gained `parameters`/`gradients`, networks lagged, GPs stayed outside the shared surface, and each family tended to reimplement downhill steps. Students then see fragmented “fit by gradients” stories instead of one loop.

## Detailed Description

### Current State (2026-09-29)
Shipped already:
- `mlai/optimisation.py`: `Optimiser` base, `SGD`, `Adam`, `train_model`
- Exported from `mlai` (`Optimiser`, `SGD`, `Adam`, `train_model`)
- `parameters` / `gradients` on key linear-model and neural-network types
- Unit + integration tests in `tests/unit/test_optimisation.py` (22 passing), including SGD on `LM` and Adam on `NeuralNetwork`

Still open (tracked in Related Backlog):
- Gaussian processes lack the shared `parameters` / `gradients` surface (GP has `objective()` only)
- Extra algorithms from the original plan (RMSprop, Adagrad, AdamW, LBFGS) and training utilities (LR schedules, early stopping, gradient clipping)
- Broader “remove every model-specific training path” cleanup — only pursue where teaching still hits bespoke loops

### Design (HOW)
1. **Shared surface**: trainable teaching models expose `parameters` and `gradients` (and an objective where natural)
2. **Optimiser module**: `Optimiser.step(model)` updates `model.parameters` from `model.gradients`
3. **Course-first algorithms**: SGD and Adam are the required core; further algorithms are additive
4. **Integration**: prefer `train_model` / optimiser steps over forking per-model trainers

## Backward Compatibility
