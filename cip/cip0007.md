# CIP-0007: Implement Unified Optimization Interface and Algorithms

## Status
- [x] Proposed
- [x] Accepted
- [x] In Progress
- [x] Implemented
- [ ] Closed

## Summary
Implement a unified optimization interface for trainable models and a shared optimiser module so course-relevant first-order methods (SGD, Adam, …) can drive more than one model family. This is the HOW for [REQ-0007](../requirements/req0007_shared-optimization-surface.md).

## Motivation
Different model types historically used inconsistent training hooks: linear models gained `parameters`/`gradients`, networks lagged, GPs stayed outside the shared surface, and each family tended to reimplement downhill steps. Students then see fragmented “fit by gradients” stories instead of one loop.

## Detailed Description

### Current State (2026-11-18)
Shipped:
- `mlai/optimisation.py`: `Optimiser` base, `SGD`, `Adam`, `train_model`
- Exported from `mlai` (`Optimiser`, `SGD`, `Adam`, `train_model`)
- `parameters` / `gradients` on key linear-model and neural-network types
- `GP.parameters` / `GP.gradients` in log space (noise + scalar kernel hyperparameters), with correct `slogdet` NLL
- Unit + integration tests in `tests/unit/test_optimisation.py` and `TestGPSharedOptimizationSurface` (SGD/Adam reduce GP NLL; finite-difference gradient check)

Still open (optional backlog only):
- Extra algorithms (RMSprop, Adagrad, AdamW, LBFGS) and training utilities (LR schedules, early stopping, gradient clipping)
- Broader “remove every model-specific training path” cleanup — only pursue where teaching still hits bespoke loops

### GP hyperparameter surface (HOW)
- Flat vector: `[log(σ²), log(θ₁), …]` for each scalar entry in `kernel.parameters`
- Materialises covariance-function defaults so `Kernel(eq_cov)` exposes variance/lengthscale
- Analytic NLL gradient via `(K⁻¹ − ααᵀ)`; kernel `∂K/∂θ` by central finite differences
- Chain rule into log space for unconstrained SGD/Adam steps

### Design (HOW)
1. **Shared surface**: trainable teaching models expose `parameters` and `gradients` (and an objective where natural)
2. **Optimiser module**: `Optimiser.step(model)` updates `model.parameters` from `model.gradients`
3. **Course-first algorithms**: SGD and Adam are the required core; further algorithms are additive
4. **Integration**: prefer `train_model` / optimiser steps over forking per-model trainers

## Backward Compatibility
Additive: existing model APIs remain; new optimiser interface sits beside older training helpers until teaching snippets migrate. GP prediction shapes for 1d `y` are unchanged; `logdetK` now stores `log|Ky|` (was incorrectly `det(Ky)`).

## Testing Strategy
- Unit tests for each optimiser (`test_optimisation.py`)
- Integration: same optimiser against linear models, networks, and GP
- Finite-difference checks for GP gradients against `objective()`
