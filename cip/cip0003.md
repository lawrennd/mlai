# CIP-0003: Complete Docstring Updates for mlai.plot Module

## Status
- [x] Proposed
- [x] Accepted
- [x] In Progress
- [ ] Implemented
- [ ] Closed

## Summary
Bring `mlai.plot` documentation to a consistent Sphinx/reST standard so plotting APIs are teachable and autodoc-complete ([REQ-0003](../requirements/req0003_plot-api-documentation.md)). Large Sphinx-style batches are already done; remaining work is a quality pass on thin stubs and fixing the duplicate `kronecker_illustrate` definition.

## Motivation
Plotting helpers carry the mathematics of lectures. Incomplete or inconsistent docstrings weaken autodoc, slow contributors, and obscure teaching intent. The original “missing docs” crisis is largely gone; the live gap is uneven *quality* across the long tail of helpers.

## Detailed Description

### Current State (2026-09-29)
- Module docstring present; Sphinx `docs/api/plot.rst` uses `automodule`
- Roughly 85 public functions and 2 public classes all have a docstring of some form
- About 50+ already use Sphinx-style `:param:` / Parameters documentation (Batches 1–3 and later work)
- About ~30 remain prose-only or stub-length (insufficient for REQ-0003’s “well enough to teach and reuse”)
- Two `def kronecker_illustrate` definitions still coexist; the `direcotry` typo appears fixed
- Adjacent correctness work on `lagrange_parallel_vectors` recorded under Completed backlog

### Docstring Standards (HOW)
- Sphinx/reST with `:param:`, `:returns:`, `:raises:` where useful
- Types and defaults called out; mathematics named in teaching-facing descriptions
- Prefer small batched edits to avoid truncating the large `plot.py` file
