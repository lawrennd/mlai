# CIP-0009: Contributor packaging via uv (succeed Poetry)

## Status

- [x] Proposed - Initial idea documented
- [ ] Accepted - Approved, ready to start work
- [ ] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Replace Poetry as the contributor, CI, and release tool for `mlai` with [uv](https://docs.astral.sh/uv/). The package stays a pure-Python distribution that end users install with pip. The lockfile, editable contributor install, test and docs jobs, and the PyPI release job move to uv.

This CIP keeps [REQ-0002](../requirements/req0002_automated-verification.md) true: CI still runs the suite on proposed changes. It changes the tool that installs that suite. It also keeps the Sphinx build from [CIP-0001](cip0001.md) and the pytest workflow from [CIP-0002](cip0002.md) on a faster install path.

## Motivation

Contributor and CI setup is `snok/install-poetry` followed by `poetry install --with dev`. That step runs on the test matrix (Python 3.11 and 3.12), the lint matrix, the docs job, and the release job. Resolve and install time dominates those jobs relative to the work they exist to do.

`mlai` has no extension modules and no custom Poetry build hook. The reason GPy kept `poetry-core` for a first cutover (a Cython `build()` script) does not apply here. A full leave of Poetry is the smaller design.

Teaching installs must keep working. `pip install -e .` and a wheel on PyPI remain the end-user path. uv is the maintainer and CI tool, and an optional faster client for anyone who already has it (`uv pip install -e .`).

## Detailed Description

### What stays

| Topic | Policy |
|-------|--------|
| Distribution name | `mlai` |
| Version | `0.1.3` until a release bumps it |
| Python | `>=3.11,<4` (CI matrix 3.11 and 3.12) |
| Runtime dependencies | `pods`, `pandas`, `matplotlib`, `IPython`, `scipy`, still unpinned in `pyproject.toml` |
| Optional GPy | Still optional. Default contributor sync does not install GPy. Tests keep mocking it. |
| `daft-pgm` for contributors | Still installed with the dev group, matching `poetry install --with dev` |
| Release trigger | GitHub Release published → build → PyPI (`.github/workflows/publish.yml`) |
| Test selection | `pytest -m "not slow"` on CI |
| End users | `pip install -e .` from a clone, or `pip install mlai` from PyPI |

### What changes

| Area | Today (Poetry) | Target (uv) |
|------|----------------|-------------|
| Contributor install | `poetry install` | `uv sync` |
| Run tests | `poetry run pytest …` | `uv run pytest …` |
| Docs build | `poetry run make html` | `uv run make html` |
| Lockfile | `poetry.lock` (Poetry 1.8.2) | `uv.lock` committed; `poetry.lock` removed |
| CI bootstrap | `snok/install-poetry@v1` plus a `.venv` cache keyed on `poetry.lock` | `astral-sh/setup-uv` |
| Build | `poetry build` | `uv build` |
| Publish | `poetry publish` with `POETRY_PYPI_TOKEN_PYPI` | `uv publish` with `UV_PUBLISH_TOKEN` set from `secrets.PYPI_API_TOKEN` |
| Version check | `poetry version -s` | `[project].version` in `pyproject.toml`, also compared with `mlai.__version__` |
| Lint extra | `poetry run pip install flake8` outside the lock | `flake8` in the dev group, so the lock owns it |
| Metadata | `[tool.poetry]` | PEP 621 `[project]` |
| Build backend | `poetry-core` | `hatchling` |

### Proposed decisions

These are the defaults for review. Accept can revise them before any code moves.

1. **Build backend is hatchling.** There is no custom build script. Set `packages = ["mlai"]` explicitly. `tests/` contains `__init__.py`, so hatchling auto-discovery would risk shipping the test tree. The wheel contains the `mlai` package and leaves out `tests/`, `docs/`, `cip/`, and `backlog/`.

2. **Dev dependencies become a PEP 735 group.** Poetry's `[tool.poetry.group.dev]` becomes `[dependency-groups] dev`. uv treats `dev` as the default group, so `uv sync` matches today's `poetry install --with dev` for contributors. Members: Sphinx and its theme and extensions, pytest and plugins, hypothesis, `daft-pgm`, and flake8.

3. **Extras get valid names.** Poetry extras are `"graphical models"` (`daft-pgm`), `"mountain car demo"` (`GPy`), and `"GP Tutorials"` (`GPy`). PEP 621 extra names cannot contain spaces. The installation guide never tells anyone to pass those extra names; it says `pip install GPy`. Rename on the way to `[project.optional-dependencies]`:

   - `graphical-models` → `daft-pgm`
   - `mountain-car` → `GPy`
   - `gp-tutorials` → `GPy`

   Two extras that both pull `GPy` stay, so a later doc can point at one tutorial or the other. Collapsing them is a docs choice, not required for the move.

4. **One lockfile.** Commit `uv.lock`. Delete `poetry.lock`. PyPI installs of the built wheel do not consult the lockfile. Contributor and CI installs do.

5. **Version source of truth is `[project].version`.** `mlai/__init__.py` still defines `__version__ = "0.1.3"`. The release job fails unless the git tag, `[project].version`, and `mlai.__version__` are the same string. This CIP does not switch runtime version lookup to `importlib.metadata`.

6. **Publish keeps the existing token.** The release job already has `id-token: write`. Trusted publishing can replace the API token later. This cutover maps `secrets.PYPI_API_TOKEN` to `UV_PUBLISH_TOKEN` so a PyPI trusted-publisher setup is not a blocker. `uv build`, then `uvx twine check dist/*`, then `uv publish`. Twine stays off the dev group.

7. **Runtime pins stay loose in `pyproject.toml`.** `pods`, `pandas`, `matplotlib`, `IPython`, and `scipy` remain unpinned there. `uv.lock` records the resolved set for CI and contributors, which is what `poetry.lock` does today. Raising floors is out of scope.

8. **Classifiers match `requires-python`.** The Poetry classifiers still advertise Python 3.6. The `[project]` table advertises Python 3.11 and 3.12, consistent with `requires-python` and the CI matrix.

### Command map

| Poetry | uv |
|--------|-----|
| `poetry install` / `poetry install --with dev` | `uv sync` |
| `poetry run …` | `uv run …` |
| `poetry build` | `uv build` |
| `poetry publish` | `uv publish` |
| `poetry version -s` | read `[project].version` |

### Files this cutover touches

- `pyproject.toml`
- `poetry.lock` (removed) and `uv.lock` (added)

## Implementation Plan

1. **Convert metadata.** Rewrite `pyproject.toml` to the shape in the decisions above. `uvx migrate-to-uv` is a reasonable starting diff; review it against those decisions before keeping it (extras names, hatchling package list, flake8, no `poetry-core`).
2. **Lock.** Run `uv lock`. Commit `uv.lock`. Remove `poetry.lock`.
3. **CI.** Switch the four workflows to `astral-sh/setup-uv` and the command map. Drop the Poetry action and the `poetry.lock` cache key.
4. **Docs.** Lead `README.md` and `docs/installation.rst` with `uv sync`, and keep a pip editable install beside it. Update the Poetry paragraph in `docs/whats_next_script.md`.
5. **Check locally.** `uv sync`, `uv run pytest -m "not slow"`, `uv build`, import `mlai` from the wheel, and confirm the wheel file list is only the `mlai` package.
6. **Release path.** Dry-run the version comparison and `uvx twine check` on the built dists. Publish itself waits for the next real release tag.

Backlog tasks wait until this CIP is Accepted.

## Backward Compatibility

Contributors who use Poetry today switch to uv. `poetry install` stops working once `poetry.lock` and `[tool.poetry]` are gone.

`pip install -e .` continues to work for a clone. `pip install mlai` continues to work for a published wheel. Students who never installed Poetry see a shorter install section, with pip still documented.

The three Poetry extra names with spaces were not part of the installation guide. Scripts that passed them to Poetry will need the new extra names. No in-repo caller does that.

GPy and daft remain optional imports. Missing them still raises the same import errors inside the plotting helpers.

## Testing Strategy

- `uv sync` on Python 3.11 completes and `uv run python -c "import mlai"` prints version `0.1.3`.
- `uv run pytest -m "not slow"` matches the current CI selection.
- `uv build` produces an sdist and a wheel. The wheel contains `mlai/` and does not contain `tests/`.
- `uvx twine check dist/*` passes.
- Docs job equivalent: `uv run make html` from `docs/`.
- GitHub Actions: Tests, Lint, and the docs workflow green on the cutover pull request, on 3.11 and 3.12 where the workflow already matrices them.
- Release workflow is reviewed against a tag-shaped version check. The first real `uv publish` is the verification that closes the CIP, or an explicit note if no release is cut before close.
