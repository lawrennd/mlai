# CIP-0009: Contributor packaging via uv (succeed Poetry)

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [x] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Replace Poetry as the contributor, CI, and release tool for `mlai` with [uv](https://docs.astral.sh/uv/). The package stays a pure-Python distribution that end users install with pip. The lockfile, editable contributor install, test and docs jobs, and the PyPI release job move to uv.

This CIP keeps [REQ-0002](../requirements/req0002_automated-verification.md) true: CI still runs the suite on proposed changes. It changes the tool that installs that suite. It also keeps the Sphinx build from [CIP-0001](cip0001.md) and the pytest workflow from [CIP-0002](cip0002.md) on a faster install path.

## Motivation

Contributor and CI setup is `snok/install-poetry` followed by `poetry install --with dev`. That step runs on the test matrix (Python 3.11 and 3.12), the lint matrix, the docs job, and the release job. Resolve and install time dominates those jobs relative to the work they exist to do.

`mlai` has no extension modules and no custom Poetry build hook. The reason GPy kept `poetry-core` for a first cutover (a Cython `build()` script) does not apply here. A full leave of Poetry is the smaller design.

Teaching installs must keep working. `pip install -e .` and a wheel on PyPI remain the end-user path. uv is the maintainer and CI tool, and an optional faster client for anyone who already has it (`uv pip install -e .`).

## Detailed Description

### What stays

| Topic | Policy |
|-------|--------|
| Distribution name | `mlai` |
| Version | `0.1.3` until a release bumps it |
| Python | `>=3.11,<4` (CI matrix 3.11 and 3.12) |
| Runtime dependencies | `pods`, `pandas`, `matplotlib`, `IPython`, `scipy`, still unpinned in `pyproject.toml` |
| Optional GPy | Still optional. Default contributor sync does not install GPy. Tests keep mocking it. |
| `daft-pgm` for contributors | Still installed with the dev group, matching `poetry install --with dev` |
| Release trigger | GitHub Release published → build → PyPI (`.github/workflows/publish.yml`) |
| Test selection | `pytest -m "not slow"` on CI |
| End users | `pip install -e .` from a clone, or `pip install mlai` from PyPI |

### What changes

| Area | Today (Poetry) | Target (uv) |
|------|----------------|-------------|
| Contributor install | `poetry install` | `uv sync` |
| Run tests | `poetry run pytest …` | `uv run pytest …` |
| Docs build | `poetry run make html` | `uv run make html` |
| Lockfile | `poetry.lock` (Poetry 1.8.2) | `uv.lock` committed; `poetry.lock` removed |
| CI bootstrap | `snok/install-poetry@v1` plus a `.venv` cache keyed on `poetry.lock` | `astral-sh/setup-uv` |
| Build | `poetry build` | `uv build` |
| Publish | `poetry publish` with `POETRY_PYPI_TOKEN_PYPI` | `uv publish` with `UV_PUBLISH_TOKEN` set from `secrets.PYPI_API_TOKEN` |
| Version check | `poetry version -s` | `[project].version` in `pyproject.toml`, also compared with `mlai.__version__` |
| Lint extra | `poetry run pip install flake8` outside the lock | `flake8` in the `dev` group, so the lock owns it |
| Metadata | `[tool.poetry]` | PEP 621 `[project]` |
| Build backend | `poetry-core` | `hatchling` |

### Accept decisions (2026-11-13)

Proceed with the proposed decisions as written:

1. **Build backend:** hatchling with `packages = ["mlai"]`.
2. **Dev group:** PEP 735 `[dependency-groups] dev`, including flake8; uv default group.
3. **Extras:** `graphical-models`, `mountain-car`, `gp-tutorials`.
4. **Lockfile:** `uv.lock` only.
5. **Version SoT:** `[project].version` checked against `mlai.__version__` and the release tag.
6. **Publish:** `UV_PUBLISH_TOKEN` from existing `PYPI_API_TOKEN`; twine via `uvx`.
7. **Runtime pins:** stay loose in `pyproject.toml`.
8. **Classifiers:** Python 3.11 and 3.12.

Command map: `poetry install --with dev` → `uv sync`; `poetry run …` → `uv run …`;
`poetry build` → `uv build`; `poetry publish` → `uv publish`.

### Files this cutover touches

- `pyproject.toml`
- `poetry.lock` (removed) and `uv.lock` (added)
- `.github/workflows/tests.yml`
- `.github/workflows/lint.yml`

- `.github/workflows/publish.yml`

Library modules stay as they are. Optional imports of `GPy` and `daft` stay optional.

## Implementation Plan

1. **Convert metadata.** Rewrite `pyproject.toml` to the Accept decisions.
2. **Lock.** Run `uv lock`. Commit `uv.lock`. Remove `poetry.lock`.
3. **CI.** Switch the four workflows to `astral-sh/setup-uv` and the command map.
4. **Docs.** Lead `README.md` and `docs/installation.rst` with `uv sync`; keep pip editable.
5. **Check locally.** `uv sync`, `uv run pytest -m "not slow"`, `uv build`, wheel import.
6. **Release path.** Version comparison and `uvx twine check` on built dists.

## Backward Compatibility

Contributors who use Poetry today switch to uv. `poetry install` stops working once `poetry.lock` and `[tool.poetry]` are gone.

`pip install -e .` continues to work for a clone. `pip install mlai` continues to work for a published wheel.

The three Poetry extra names with spaces were not part of the installation guide. Scripts that passed them to Poetry will need the new extra names.

## Testing Strategy

- `uv sync` completes and `uv run python -c "import mlai"` prints version `0.1.3`.
- `uv run pytest -m "not slow"` matches the current CI selection.
- `uv build` produces an sdist and a wheel. The wheel contains `mlai/` and does not contain `tests/`.
- `uvx twine check dist/*` passes.
- GitHub Actions: Tests, Lint, and the docs workflow green on the cutover pull request.
